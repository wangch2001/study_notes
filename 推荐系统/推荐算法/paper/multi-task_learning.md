# 多任务学习
在推荐系统中一般指多目标学习(multi-label learing)
多任务学习可以同时对数个目标进行建模预测，且不用针对不同的任务训练不同的模型，工程上便利。

但是多任务学习也会出现跷跷板问题(PLE)，且目标相关性较差的时候会出现负迁移(MMOE)

**shared-bottom**
早期的多任务模型都是shared-bottom底层共享，通过共享底层模块，学习任务间通用的特征表征，再往上针对每一个任务设置一个Tower网络，每个Tower网络的参数由自身对应的任务目标进行学习
**参数硬共享**
共享特征提取层，共享层的参数对于所有任务都相同如ESSM，计算效率高，共享程度高，但是效果上收到目标差异的影响较大，出现负迁移
**参数软共享**
任务之间共享部分参数，但是每个任务可以有自己的任务特定参数如MMOE、PLE，模型更为灵活能平衡任务之间的独立性。

#### ESSM
通过CTCVR和CTR两个任务辅助CVR学习  ctcvr=ctr*cvr
传统的CVR预估存在着样本选择偏差(训练数据和测试数据并非独立同分布)和稀疏数据的问题
ESMM的出发点就是：
建立CTR与CVR这两个塔，共享底座embedding。
既然CTCVR和CTR这两个任务训练是可以使用全部有曝光样本的，那我们通过这学习两个任务，隐式地来学习CVR任务。loss直接相加
用除法的话因为浮点数差异会影响结果

#### MMOE
对于多个优化任务，引入了多个专家进行不同的决策和组合，最终完成多目标的预测
- 将特征输入多个结构相同，但不共享参数的专家神经网络
- 接下来，建立多个门控网络，得到每个专家的权重，把每个专家的输出加权组合得到门控网络最终的输出
- 用最终的向量通过不同的塔预估业务指标
**MMOE存在极化问题**
某一权重过小导致没有将输出融合，而是简单使用了一个专家。
**通过dropout解决极化问题**
解决极化现象的一种方法是dropout
在训练的过程中被softmax输出使用dropout
对于softmax输出的N个数值（N为专家的个数），每个数值都有10%的概率被mask
也就是说在训练的过程中，每个专家被丢弃的概率都是10%。
强迫每个任务根据部分专家做预测
**缺点**
MMOE中所有的Expert是被所有任务所共享，这可能无法捕捉到任务之间更复杂的关系，从而给部分任务带来一定的噪声。
在复杂任务机制下，MMOE不同专家在不同任务的权重学的差不多
不同的Expert之间没有交互，联合优化的效果有所折扣
#### PLE
解决负迁移和跷跷板问题
对这一任务采用两个指标
VCR：播放完成率，播放时间占视频时长的比例，回归任务
VTR：有效播放率，播放时间是否超过某个阈值，分类任务
**两大结构上改进**
- CGC定制门控，把MMOE中提出的Expert分成两种，任务特定task-specific和任务共享task-shared。可以让task-specific expert只受自己任务梯度的影响，不会受到其他任务的干扰。
- PLE分层萃取，将上述CGC网络的多层纵向叠加，以获得更加丰富的表征能力。Gate设计成两种类型，使得不同类型Expert信息融合交互。task-share gate融合所有Expert信息，task-specific gate只融合specific expert和share expert。
**多任务loss联合优化**
原有的loss加权和不同任务之间的样本空间不一致，且权重独立要设置
PLE将训练样本空间作为全部任务样本空间的并集，在分别针对每个任务算loss时，只考虑该任务的样本的空间
随着迭代次数的增加，任务的权重应当不断衰减
