# OneRec

论文地址：

V1：https://arxiv.org/abs/2502.18965

V2：http://arxiv.org/abs/2506.13695

方法框架：

+ 创新点一：one-stage
+ 创新点二：引入MoE架构
+ 创新点三：生成式推荐
+ 创新点四：迭代偏好对齐（IPA）

技术实现：

+ 基础模型采用 **序列到序列生成结构**，输入用户历史交互序列，输出推荐物品序列；
+ 使用 **对比学习 (contrastive learning)** 与 **生成目标 (generative loss)** 联合训练；
+ 通过 **偏好对齐算法**，在训练后阶段不断修正推荐结果，提升长期效果。

贡献与意义：

1. **提出统一范式**：首次将召回与排序整合到一个生成框架中。
2. **引入对齐机制**：借鉴 RLHF，将用户偏好对齐引入推荐系统。
3. **提升性能与简化架构**：在保证高性能的同时简化推荐系统设计，具有实践意义。

# OneRec 模型架构详解

## 1. 整体流程概览

OneRec 输入 **用户历史行为序列**（例如交互过的物品 ID/文本/嵌入），输出一个 **候选物品序列**，同时完成 **召回** 和 **排序**。
 架构主要由三部分组成：

1. **输入编码器 (Encoder)**：建模用户兴趣。
2. **生成式推荐器 (Generative Recommender, Decoder)**：端到端生成推荐列表。
3. **迭代偏好对齐 (Iterative Preference Alignment, IPA)**：利用奖励信号优化推荐结果。

------

## 2. 输入编码器 (User Behavior Encoder)

- 输入：用户交互序列 {i1,i2,...,in}，每个 ik 可以是 **物品 ID、文本描述、属性 embedding**。
- 编码方式：
  - 采用 **Transformer 编码器** 或 **序列建模器** (如 GRU/Transformer-based encoder) 捕捉用户长期兴趣。
  - 输出：用户表征向量 hu。
- 特点：
  - 不仅保留了 **用户历史偏好**，还为 **生成阶段** 提供上下文信息。

------

## 3. 生成式推荐器 (Generative Recommender, Decoder)

核心思想：把推荐任务转化为 **序列生成任务**。

- **模型结构**：基于 **序列到序列 (Seq2Seq)** 框架。

  - 输入：用户表示 hu；
  - 输出：推荐物品序列 {o1,o2,...,om}。

- **生成方式**：

  - **物品 ID 生成**：直接生成候选物品 ID（适用于 ID 较少的情况）；
  - **物品 token 生成**：通过生成物品属性/embedding 表示，再映射到物品集合（适合大规模推荐场景）。

- **损失函数 (训练目标)**：

  1. **生成损失 (Generative Loss)**：最大化推荐序列的似然概率；

     $\mathcal{L}_{gen}=-\sum_t\log P(o_t|o_{<t},h_u)$

  2. **对比损失 (Contrastive Loss)**：通过正负样本区分，提高推荐的判别性。
      （保证生成的物品与用户兴趣相似，而非兴趣物品被拉开距离。）

------

## 4. 迭代偏好对齐 (Iterative Preference Alignment, IPA)

这一部分是 OneRec 的创新点，借鉴了 **RLHF (人类反馈强化学习)** 的思想：

### (1) 奖励建模 (Reward Modeling)

- 奖励信号来源：
  - **排序相关性 (ranking reward)**：推荐物品排序越合理，奖励越高；
  - **用户反馈 (user feedback)**：点击、停留时间、转化率等行为作为奖励信号。

### (2) 对齐过程

- 采用类似 **策略优化 (Policy Optimization)** 的过程：
  - 生成推荐序列 → 根据奖励信号计算回报 → 反向更新生成器参数。
- 通过 **多轮迭代**，模型逐渐与用户真实偏好对齐。

### (3) 效果

- 保证推荐不仅仅是“生成可能相关的物品”，而是“生成用户真正喜欢的排序列表”；
- 改善了传统生成推荐中 **偏离用户需求** 的问题。
