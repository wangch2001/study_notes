## A/B测试

A/B测试是什么？（例如）

+ 召回团队实现了一种GNN召回通道离线实验结果正向
+ 下一步是做线上的小流量A/B测试，考察新的召回通道对线上指标的影响。
+ 模型中有一些参数，比如GNN的深度取值∈{1,2,3}，需要用A/B测试选取最优参数。

意义：

+ 做线上小流量A/B测试，考察新方法对线上指标的影响
+ 通过A/B测试，选取最优参数
+ 实验组指标显著优于对照组，则值得推全

### 随机分桶

使用哈希函数将用户ID进行映射，分为不同的桶（也就是随机划分）

每一组应用不同的策略，测试新策略是否有效，设置对照组进行对比

### 分层实验

分层实验的目标是解决流量不够用的问题

+ **分层实验：**召回、粗排、精排、重排、用户界面、广告(例如GNN召回通道属于召回层。)
+ **同层互斥：**GNN实验占了召回层的4个桶，其他召回实验只能用剩余的6个桶
+ **不同层正交：**每一层独立随机对用户做分桶。每一层都可以独立用100%的用户做实验。

![image-20250601150121312](./assets/image-20250601150121312.png)

+ 同类的策略天然互斥，可能互相干扰，对于一个用户只能用其中一种。
+ 不同类型的策略通常不会相互干扰，可以正交。

### Holdout机制

+ 每个实验（召回、粗排、精排、重排)独立汇报对业务指标的提升
+ 公司考察一个部门（比如推荐系统)在一段时间内对业务指标总体的提升 
+ 取10%的用户作为holdout桶，推荐系统使用剩余 90%的用户做实验，两者互斥 
+ 10%holdout桶vs90%实验桶的diff（需要归一化）为整个部门的业务指标收益

 ![image-20250601151318573](./assets/image-20250601151318573.png)

+ ·每个若核周期结束之后，清除holdout桶，让推全实验从90%用户扩大到100%用户
+ 重新随机划分用户，得到holdout桶和实验桶，开始下一轮考核周期。
+ 新的holdout桶与实验桶各种业务指标的diff接近0。
+ 随着召回、粗排、精排、重排实验上线和推全，diff会逐渐扩大。

### 反转实验

+ 有的指标（点击、交互)立刻收到新策略影响，有的指标（留存)有滞后性，需要长期观测
+ 实验观测到显著收益后尽快推全新策略。目的是腾出桶供其他实验使用，或需要基于新策略做后续的开发
+ 用反转实验解决上述矛盾，既可以尽快推全，也可以长期观测实验指标
+ 在推全的新层中开一个旧策略的桶，长期观测实验指标

![image-20250601151822296](./assets/image-20250601151822296.png)

### 总结

+ **分层实验：**同层互斥（不允许两个实验同时影响一位用户)、不同层正交（实验有重叠的用户） 
+ **Holdout：**保留10%的用户，完全不受实验影响，可以考察整个部门对业务指标的贡献。
+ **实验推全：**新建一个推全层，与其他层正交。
+ **反转实验：**在新的推全层上，保留一个小的反转桶，使用旧策略。长期观测新旧策略的dff

# 召回

## 基于物品的协同过滤（ItemCF)

根据用户的喜好和其它兴趣相近的用户推荐物品

应用最广泛的：基于邻域的方法

+ UserCF：推荐相似用户喜欢的东西
+ ItemCF：推荐他人之前喜欢的物品相似的物品

**常用相似度**

+ Jaccard相关系数
+ 余弦相似度
+ 皮尔逊相关系数，相比于余弦相似度，通过用户平均分来减小偏置影响

**召回率：**预测准确的物品占用户实际喜欢物品的比例

**精确率：**对用户准确推荐的物品占总推荐物品的比例

**覆盖率：**推荐系统能够推荐出来的物品占总物品集合的比例

**协同过滤的缺点**

+ 泛化能力弱，无法将两个物品相似的信息推广到其它物品的相似性上
+ 热门物品具有很强的头部效应，容易跟大量物品产生相似，而尾部物品由于特征向量稀疏，导致很少被推荐

**什么时候用UserCF，什么时候用ItemCF，为什么？**

1. UserCF：所以具备更强的社交特性，这样的特点非常适于用户少物品多，时效性较强的场合。比如新闻推荐场景。此外，UserCF可以发现用户潜在但自己尚未察觉的兴趣爱好。
2. ItemCF：适用于兴趣变化较为稳定的应用，适合物品少，用户多，用户兴趣固定持久的场合。比如推荐音乐、电影。

## Swing算法

之前的Item-based CF只关注于ltem-User-ltem的路径，即通过物品与用户的交互，来推断物品与物品之间的相似度，从而进行推荐。忽视了噪声，推荐精度存在局限性。

 Swing通过利用User-ltem-User路径中所包含的信息进行推荐：

若用户u和用户V之间除了购买过ⅰ外，还购买过商品j，则认为两件商品是具有某种程度上的相似的。也就是说，商品与商品之间的相似关系，是通过用户关系来传递的如果这两个用户共同购买的物品越少，即这两个用户原始兴趣不相以，但仍同时购买了两个相同的物品，则物品和的相以性越高。

## 矩阵补充

+ 把物品ID、用户ID做embedding,映射成向量。
+ 两个向量的內积 < $a_u$ , $b_i$ > 作为用户u对物品i兴趣的预估。
+ 让 < $a_u$ , $b_i$ > 拟合真实观测的兴趣分数，学习模型的 embedding层参数。
+ 矩阵补充模型有很多缺点，效果不好。

缺点1：仅用ID embedding，没利用物品、用户信息

+ 物品属性：类目、关键词、地理位置、作者信息
+ 用户属性：性别、年龄、地理位置、感兴趣的类目
+ 双塔模型可以看做矩阵补充的升级版

缺点2：负样本的选取方式不对

+ 样本：用户--物品的二元组，记作（u，i）
+ 正样本：曝光之后，有点击、交互（正确的做法）
+ 负样本：曝光之后，没有点击、交互（错误的做法）

缺点3：做训练的方法不好

+ 内积 < $a_u$ , $b_i$ > 不如余弦相似度
+ 用平方损失（回归），不如用交叉熵损失（分类）

**训练方式：**

1. Pointwise：独立看待每个正样本、负样本，做简单的二元分类

   + 把召回看作二分类任务
   + 对于正样本，鼓励 cos(a, b) 接近+1
   + 对于负样本，鼓励 cos(a, b) 接近-1
   + 正负样本数量控制在1：2或1：3

2. Pairwise：每次取一个正样本、一个负样本

   + 每次输入三元组 <用户a， 正样本b+，负样本b->

   + 基本想法：鼓励 cos(a, b+) 大于 cos(a, b-)

   + 超参数m，正负样本的兴趣之差

   + ![image-20250604102537734](./assets/image-20250604102537734.png)

   + 可以通过最小化以下损失函数来训练双塔模型

     ![image-20250604101751993](./assets/image-20250604101751993.png)

3. Listwise：每次取一个正样本、多个负样本

   + 每次输入一个用户，一个正样本，多个负样本
   + 同样是鼓励 cos(a, b+) 尽量大，cos(a, b-) 尽量小
   + 将 cos(a, b+) 和所有cos(a, b-) 输入softmax进行归一化
   + ![image-20250604102755269](./assets/image-20250604102755269.png)
   + 利用交叉熵做损失函数，训练时最小化交叉熵，使得s+接近y+=1，s-接近y-=0

+ 用户塔、物品塔各输出一个向量。
+ 两个向量的余弦相似度作为兴趣的预估值。
+ 三种训练方式：
  + Pointwise：每次用一个用户、一个物品（可正可负)
  + Pairwise：每次用一个用户、一个正样本、一个负样本
  + Listwise：每次用一个用户、一个正样本、多个负样本

## 双塔模型：正负样本

**正样本：**

+ 曝光且有点击的用户物品二元组
+ 问题：少部分物品占据大量点击导致正样本多是热门物品
+ 解决方法：对冷门物品过采样（采样多次），对热门物品降采样（抛弃一些样本）

**负样本：**

+ 简单负样本

  + 全体物品

    均匀抽样？

    对冷门不公平-因为正样本大多是热门物品，导致负样本中热门物品占比少

    解决方法：非均匀抽样一物品抽样的概率与热门程度正相关

    抽样概率∝点击次数0.75

    使得热门物品成为负样本的概率大

  + batch内负样本

    ![image-20250604104618263](./assets/image-20250604104618263.png)

    但这种负样本中，抽样概率∝点击次数，热门物品成为负样本的概率过大

    解决方法：将用户的兴趣调整为 $cos(\mathrm{a,b_i)-}\log p_i$

    其中 $p_i$ ∝点击次数

+ 困难负样本

  1. 被粗排淘汰的物品（比较困难）
  2. 精排分数靠后的物品（非常困难）

+ 对正负样本做二元分类

  + 全体物品（简单）分类准确率高
  + 被粗排淘汰的物品（比较困难）容易分错
  + 精排分数靠后的物品（非常困难）更容易出错

+ 工业常用做法

  + 混合几种负样本
  + 50%的负样本是全体物品（简单负样本)
  + 50%的负样本是没通过排序的物品（困难负样本)

![image-20250604105409447](./assets/image-20250604105409447.png)

**总结**

+ 正样本：曝光而且有点击
+ 简单负样本：
  + 全体物品
  + batch内负样本
+ 困难负样本：被召回，但是被排序淘汰
+ 错误：曝光、但是未点击的物品做召回的负样本
