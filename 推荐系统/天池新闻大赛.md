# 天池新闻大赛

赛题以预测用户未来点击新闻文章为任务，数据集报名后可见并可下载，该数据来自某新闻APP平台的用户交互数据，包括30万用户，近300万次点击，共36万多篇不同的新闻文章，同时每篇新闻文章有对应的embedding向量表示。为了保证比赛的公平性，将会从中抽取20万用户的点击日志数据作为训练集，5万用户的点击日志数据作为测试集A，5万用户的点击日志数据作为测试集B。

## 1. `data.py` — 数据准备

- 从 `train_click_log.csv` 和 `testB_click_log_Test_B.csv` 读取用户点击数据；
- 将每个用户的最后一条点击行为作为验证集样本；
- 生成：
  - `click.pkl`: 用户历史点击行为；
  - `query.pkl`: 需要预测的目标文章（包括验证和测试用户）。

## 2. `recall_itemcf.py` — ItemCF 召回

- 使用**物品协同过滤（ItemCF）**计算文章相似度；
- 考虑文章点击的顺序权重（距离越近权重越高）；
- 为每个用户召回与最近浏览文章相似的文章；
- 保存召回结果 `recall_itemcf.pkl`。

## 3. `recall_binetwork.py` — 二部图召回（BiNetwork）

- 构建用户–文章二部图；
- 计算基于共现的相似度：
- $$sim(i,j)=\sum_u\frac1{\log(|U_i|+1)\log(|I_u|+1)}$$
- 从相似文章中召回候选集；
- 输出 `recall_binetwork.pkl`。

## 4. `recall_w2v.py` — Word2Vec 向量召回

- 把用户点击序列视为句子，用 **Word2Vec** 训练文章 embedding；
- 使用 Annoy 构建近邻索引；
- 根据最近点击文章的 embedding 召回相似文章；
- 输出：
  - 文章向量 `article_w2v.pkl`
  - 召回结果 `recall_w2v.pkl`

## 5. `recall.py` — 多路召回融合

- 读取三种召回结果：`itemcf`、`binetwork`、`w2v`；
- 对每个召回结果进行归一化（min-max scaling）；
- 设置加权融合权重（如 itemcf:1, binetwork:1, w2v:0.1）；
- 去重合并后生成统一候选集 `recall.pkl`；
- 同时计算召回覆盖率与一致性指标。

## 6. `rank_feature.py` — 特征工程

为排序模型生成丰富特征，包括：

- **用户行为特征**
  - 平均点击间隔、最后点击时间差、点击文章字数统计；
- **文章内容特征**
  - 发布时间、字数、分类；
- **召回相似度特征**
  - 与用户最后一次点击文章的 ItemCF、BiNetwork、W2V 相似度；
- 输出 `feature.pkl` 供排序模型使用。

## 7. `rank_lgb.py` — 排序模型（LightGBM）

- 使用 `GroupKFold(5)` 按用户划分交叉验证；
- 模型目标为预测 `label=1`（点击目标文章）；
- 输出：
  - 模型文件 `lgb0.pkl ~ lgb4.pkl`
  - 预测结果 `../prediction_result/result.csv`
- 离线阶段会计算 HitRate@K、MRR@K 指标；
- 在线阶段用已保存模型预测。

## 🧱 一、项目总体概览

### 🎯 项目目标

## 🔁 三、召回阶段（Recall Stage）

### 🎯 目标

为每个用户召回一批候选文章。

共实现三种不同算法：

| 模块                  | 方法      | 思想                       |
| --------------------- | --------- | -------------------------- |
| `recall_itemcf.py`    | ItemCF    | 基于物品相似度的协同过滤   |
| `recall_binetwork.py` | BiNetwork | 用户–物品二部图传播        |
| `recall_w2v.py`       | Word2Vec  | 基于用户行为序列的向量召回 |

------

### （1）ItemCF召回 — `recall_itemcf.py`

#### 🧠 核心思想

如果两个文章被相似用户群反复共同点击，它们就相似。
 推荐时，对用户点击过的文章，找到相似的文章。

#### ⚙️ 实现流程

1. **构建用户–文章倒排表**

   ```python
   user_item_dict = df.groupby('user_id')['click_article_id'].agg(list)
   ```

2. **计算文章间相似度**

   - 对每个用户的点击序列，按距离衰减叠加权重；
   - 使用 log 惩罚活跃用户；
   - 最终归一化：
      $$[
      sim(i,j)=\frac{c_{ij}}{\sqrt{N_iN_j}}
      ]$$

3. **召回阶段**

   - 对每个用户最近点击的 1-2 篇文章；
   - 查找相似文章前200；
   - 累积分数并保留Top100；
   - 保存至 `../user_data/data/offline/recall_itemcf.pkl`

ItemCF 的相似度计算基于用户的共现点击行为，
 在这个项目中进一步引入了：

- 点击顺序权重（方向区分）
- 距离衰减（相邻点击影响更大）
- 用户活跃度惩罚（防止高频用户主导）
   并对共现值做归一化。

最终得到的 `sim_dict` 即是文章间的相似度矩阵，用于后续召回推荐。

**相似度计算：**

+ 计算物品（A，B）的共现次数，假设为2，那么将其作为分子
+ 假设一用户行为序列中出现(A, B)，则loc_weight = 1.0
+ 假设另一用户序列中出现(B, A)则loc_weight = 0.7 (反向点击)
+ 则相似度 = （1.0 + 0.7）/ 2
+ 对于一些距离较大的组合，比如(A, C)，则加入距离衰减，衰减系数为0.9
+ 点击文章多的用户权重更低：`/log(1+len(items))`，对于点击文章的多的用户，即使其出现了(A, B)，但其所占权重较低
+ 若某文章非常热门（被所有人点过），它与任何文章的共现值都会高，需要归一化。于是引入标准 ItemCF 公式：$$\sin(i,j)=\frac{\sum_{u\in U_{ij}}1}{\sqrt{|U_i|\times|U_j|}}$$

### （2）二部图召回 — `recall_binetwork.py`

#### 🧠 核心思想

构建用户–文章的**二部图（BiGraph）**，通过共现传播建立文章相似度：

> 如果同一批用户同时点击了 A、B，则 A、B 相关。

#### ⚙️ 实现流程

1. **生成文章→用户、用户→文章映射**
2. **相似度计算**
   $$ [
    sim(i,j) = \sum_{u\in U_{ij}} \frac{1}{\log(|U_i|+1)\log(|I_u|+1)}
    ]$$
3. **召回Top50相似文章**
4. **输出召回结果 `recall_binetwork.pkl`**

它的目标与 ItemCF 相同：为每个用户召回一批可能感兴趣的文章。
 但算法思想完全不同：它不是仅看文章间共现，而是从“用户–文章二部图”的角度构建物品相似关系。

**基于二部图的文章相似度计算**

核心思想是：

> 如果两个文章被许多相似的用户点击过，它们就相似。

$$sim(i,j)=\sum_{u\in U_{ij}}\frac1{\log(|U_i|+1)\times\log(|I_u|+1)}$$

含义：

- Ui：点击过文章 i 的所有用户；
- Iu：用户 u 点击过的所有文章；
- 权重项 $1 / (\log|U_i|\log|I_u|)$
  - 惩罚热门文章；
  - 惩罚活跃用户。

这个公式其实是 **对“共现矩阵”的加权版本**，
 它融合了用户活跃度与文章流行度的双重正则。

简而言之：

> ItemCF 强调时间序列上的点击顺序，
>  而 BiNetwork 强调全局共现结构，更“均衡”。

### （3）Word2Vec召回 — `recall_w2v.py`

#### 🧠 核心思想

把用户点击序列当作句子，文章ID当作词，用 Word2Vec 学习文章的“语义相似度”。

Word2Vec召回在捕捉“潜在兴趣迁移”上最强，
 它能发现那些**不直接共现但语义相近**的文章。

#### ⚙️ 实现流程

1. **训练 Word2Vec 模型**

   ```python
   model = Word2Vec(sentences, vector_size=256, window=3, sg=1)
   ```

   输出：

   ```
   ../user_data/data/offline/article_w2v.pkl
   ```

2. **建立 ANN 索引**
    使用 Annoy 库快速查找近邻：

   ```python
   index = AnnoyIndex(256, 'angular')
   index.build(100)
   ```

3. **召回阶段**

   - 取最近点击文章的向量；
   - 在 Annoy 索引中查找前 100 相似文章；
   - 取前 50 结果；
   - 保存至 `recall_w2v.pkl`

**Word2Vec 的训练数据是用户的点击序列（即文章的ID），而不是官方提供的文章embedding向量。**
 模型通过学习“哪些文章经常被相邻点击”，得到文章的行为embedding，
 然后用这些embedding去计算文章相似度，实现召回。

+ 官方 embedding 反映“内容语义”；
+ Word2Vec embedding 反映“行为共现”。

**为什么采用Skip-gram，而不是采用CBOW？**

| 模型          | 全称                    | 预测方向           | 核心思想                      |
| ------------- | ----------------------- | ------------------ | ----------------------------- |
| **CBOW**      | Continuous Bag of Words | 从上下文预测中心词 | 平均上下文词向量 → 预测当前词 |
| **Skip-Gram** | Skip-Gram Model         | 从中心词预测上下文 | 用当前词 → 预测周围上下文     |

| 维度              | 结论                                                 |
| ----------------- | ---------------------------------------------------- |
| **训练语料**      | 用户点击序列，而非文本语料                           |
| **为何Skip-Gram** | 因为点击序列稀疏、短、顺序重要、冷门项多             |
| **Skip-Gram优势** | 对低频文章友好、保留顺序关系、能捕捉细粒度共现       |
| **CBOW不足**      | 容易平均掉稀疏信号，难处理短上下文                   |
| **结论**          | 在推荐系统的用户行为序列建模中，Skip-Gram 是默认首选 |

| 特点     | 描述               | 影响                          |
| -------- | ------------------ | ----------------------------- |
| 稀疏性高 | 用户点击文章数量少 | CBOW难以平均出稳定上下文      |
| 序列多样 | 每个用户兴趣不同   | Skip-Gram可以独立建模每次点击 |
| 顺序重要 | 点击是时间序列     | Skip-Gram天然保留顺序影响     |

✅ 1. 更适合稀疏数据

- **CBOW** 需要一个上下文窗口来预测中心词。
   当序列稀疏、上下文信息不足时，CBOW 容易平均掉有效信息；
- **Skip-Gram** 每次只用一个中心词预测周围词，能从少量共现中学习稳定信号。

👉 推荐数据往往非常稀疏，所以 Skip-Gram 更鲁棒。

✅ 2. 对低频文章更友好

Skip-Gram 在训练时：

> 每次用一个中心词预测多个上下文，
>  因此即使是低频词也能被多次学习到。

而 CBOW 则是平均上下文 → 预测中心词，
 低频中心词的梯度更新次数很少，难以学好 embedding。

👉 对推荐来说，这意味着：

> 冷门文章（低点击量）也能获得较好的 embedding 表征。

✅ 3. 对上下文顺序更敏感

Skip-Gram 可以更精确地捕捉相邻点击之间的关联。
 例如：

- 用户的点击序列是 `[军事新闻 → 政治分析 → 评论文章]`；
- Skip-Gram 会强化这些局部连续点击的语义；
- CBOW 会把它们平均化，弱化了时间顺序。

👉 在推荐任务中，**兴趣迁移路径** 很重要，而 Skip-Gram 保留了这种局部序列信息。

✅ 4. 更适合小语料场景

在自然语言中，CBOW 适合超大语料（例如 Wikipedia），
 因为它能批量平均上下文、收敛更快；
 而 Skip-Gram 更适合中小语料（例如用户点击日志）：

- 用户数几十万；
- 每人点击几十篇文章；
- 总体样本量较小。

Skip-Gram 能从少量数据中提取更多“共现关系”，对推荐任务更稳。

**训练word2vec中的负采样是什么？有什么作用？**

在 Word2Vec 训练中（无论是 CBOW 还是 Skip-Gram），
 模型的目标是学习每个词（这里是每篇文章）的向量，使得：

> 出现在相似上下文中的词 → 向量更接近；
>  不在同一上下文的词 → 向量更远。

原始训练方式计算代价太大，原始的 Word2Vec 使用的是一个**全词 softmax** 结构： $P(\text{context}|\text{word})=\frac{\exp(v_c\cdot v_w)}{\sum_{w^{\prime}\in V}\exp(v_c\cdot v_{w^{\prime}})}$

+ 词典 V 的大小可能是几万个甚至几十万；
+ 每次梯度更新都要计算整个词表的 softmax；
+ 对推荐任务（几十万篇文章）来说，**几乎不可行**。

负采样的想法非常简单：

> 不用每次都计算所有词的 softmax，只区分“正样本 vs 若干负样本”。

也就是说：

- 模型只需要区分：
  - 哪些词 **应该出现在该上下文**（正样本）；
  - 哪些词 **不应该出现**（负样本）。

**训练目标函数（逻辑回归形式）**

$$\mathcal{L}=\log\sigma(v_{w_c}\cdot v_{w_o})+\sum_{i=1}^k\mathbb{E}_{w_i\sim P_n(w)}[\log\sigma(-v_{w_i}\cdot v_{w_o})]$$

| 项         | 含义                         |
| ---------- | ---------------------------- |
| $(w_c)$    | 中心词（中心文章）           |
| $(w_o)$    | 上下文词（相邻文章）         |
| $(w_i)$    | 随机负样本                   |
| $(P_n(w))$ | 负采样分布（通常与词频有关） |
| $(\sigma)$ | sigmoid 函数                 |

优化目标：

- 让正样本$(w_c, w_o)$的内积变大（趋向相似）；
- 让负样本 $(w_c, w_i)$ 的内积变小（趋向无关）。

**损失函数：**

+ 原本 Skip-Gram 模型的目标函数是 **多分类的 softmax 交叉熵损失（multi-class softmax loss）**。多分类交叉熵（Cross-Entropy for Multi-Class Softmax）**。**
+ **引入负采样（Negative Sampling）后，它确实变成了一种二分类对比损失（binary classification loss）**。损失函数就是二分类交叉熵（Binary Cross-Entropy, BCE）

## 🔗 四、召回融合：`recall.py`

### 🧠 目的

将多个召回源（itemcf、binetwork、w2v）结果融合，形成最终候选集。

### ⚙️ 实现方法

1. **读取三种召回结果**

   ```python
   recall_methods = ['itemcf', 'w2v', 'binetwork']
   ```

2. **归一化相似度**

   不同召回模型的分数分布差异大：

   - ItemCF 相似度 ≈ 0.1~0.9；
   - BiNetwork 权重 ≈ 0~0.3；
   - W2V 相似度 ≈ 0~2。

   如果不归一化，某个召回模型分数范围更大，会在加权融合时“主导结果”。

    对每个用户的 `sim_score` 做 min-max scaling：

   ```python
   (score - min) / (max - min)
   ```

3. **加权融合**
    例如：

   ```python
   weights = {'itemcf': 1, 'binetwork': 1, 'w2v': 0.1}
   ```

4. **去重合并、按用户排序**

   - 聚合相同 `(user_id, article_id)`；
   - 按最终 `sim_score` 降序排序；
   - 输出 `recall.pkl`。

## ⚙️ 五、排序特征工程：`rank_feature.py`

### 🎯 目标

为每个候选 `(user, article)` 提取机器学习可用特征。

在完成召回（`recall.py`）后，为每个用户与候选文章对 (user_id, article_id) 提取丰富的数值特征，
 以便后续的排序模型（LightGBM）能够根据这些特征学习到更精细的兴趣匹配模式。

### 🧩 特征类别

| 类别             | 示例                                     | 含义           |
| ---------------- | ---------------------------------------- | -------------- |
| 用户行为统计     | 平均点击时间间隔、平均点击字数           | 用户活跃度     |
| 用户最后点击差值 | 当前文章发布时间 - 最后点击文章时间      | 时序相似性     |
| 点击习惯         | 平均点击时段标准差                       | 点击时间模式   |
| 内容特征         | words_count, category_id                 | 文章内容属性   |
| 相似度特征       | ItemCF相似度、W2V相似度、BiNetwork相似度 | 与历史行为关联 |

| 特征类型               | 示例                                                      | 含义                   |
| ---------------------- | --------------------------------------------------------- | ---------------------- |
| **文章内容特征**       | `words_count`, `category_id`, `created_at_ts`             | 描述候选文章本身属性   |
| **用户行为统计特征**   | `user_id_click_diff_mean`, `user_click_datetime_hour_std` | 描述用户点击习惯       |

**LightGBM**

**LightGBM 在推荐系统中的位置**

在召回阶段，我们已经为每个用户挑出了“可能感兴趣”的一批文章；
 但这批文章中**有真命中的（用户真的会点）**，也有**假命中的（模型误召的）**。

LightGBM 的任务就是：

> 学习区分“用户最终会点的文章”和“不会点的文章”。

**模型输入是什么？（Features）**

LightGBM 的输入是：

> 每一个用户–候选文章对 `(user_id, article_id)` 的特征向量。

这些特征由 `rank_feature.py` 提取，包含以下几类：

| 特征类型              | 示例                                                         | 含义                     |
| --------------------- | ------------------------------------------------------------ | ------------------------ |
| **文章内容特征**      | `words_count`, `category_id`, `created_at_ts`                | 候选文章自身属性         |
| **用户行为统计特征**  | `user_id_cnt`, `user_id_click_diff_mean`, `user_click_datetime_hour_std` | 用户活跃度与行为模式     |
| **用户-文章交互特征** | `user_last_click_words_count_diff`, `user_last_click_created_at_ts_diff` | 候选与用户历史行为的差异 |
| **召回相似度特征**    | `user_last_click_article_w2v_sim`, `user_last_click_article_itemcf_sim`, `user_last_click_article_binetwork_sim` | 候选与历史文章的相似性   |
| **交叉计数特征**      | `user_id_category_id_cnt`                                    | 用户在该类别下的点击频率 |

这些特征最终组成一个数值向量，例如👇

| user_id | article_id | feature_1 | feature_2 | feature_3 | …    | label |
| ------- | ---------- | --------- | --------- | --------- | ---- | ----- |
| 1001    | 45         | 0.87      | 0.34      | 0.12      | …    | 1     |
| 1001    | 77         | 0.23      | 0.56      | 0.74      | …    | 0     |

LightGBM 模型的输入就是这些数值特征（`feature_1, feature_2, ...`）。

**模型的训练目标是什么？（Target）**

LightGBM 在这里是一个**二分类模型**。

 训练目标：

$$\text{label}=\begin{cases}1,&\text{如果该用户最终点击了这篇文章}\\0,&\text{否则(只是被召回,但未被点击})\end{cases}$$

换句话说：

- 对于每个用户召回的一堆文章，我们知道他最终“真正点击”的那一篇；
- 于是标记那篇为 **正样本 (label=1)**；
- 其他召回但未点击的文章为 **负样本 (label=0)**。

模型学习的目标是：

> 给正样本打高分（预测概率高），
>  给负样本打低分（预测概率低）。

在 LightGBM 中，使用**二分类逻辑回归损失函数（Binary Cross-Entropy）**：

$$\mathcal{L}=-\frac1N\sum_i[y_i\log(p_i)+(1-y_i)\log(1-p_i)]$$

其中：

- $y_i \in \{0, 1\}$：真实点击标签；
- $p_i = \sigma(f(x_i))$：模型预测的点击概率。

模型通过不断分裂树节点、最小化这个损失，学习特征与“点击概率”之间的关系。

**输出是什么？（Predictions）**

模型输出每个样本的预测概率：

| user_id | article_id | pred  |
| ------- | ---------- | ----- |
| 1001    | 45         | 0.923 |
| 1001    | 67         | 0.822 |
| 1001    | 89         | 0.655 |

**LightGBM 模型怎么学习？**

LightGBM 是一种 **基于梯度提升树（GBDT）** 的模型。
 简单来说，它会逐步构建很多棵树，每一棵树都试图修正上一棵树的误差。

在本项目中，它学习的模式大致是：

| 特征                                 | 可能学习的规律                        |
| ------------------------------------ | ------------------------------------- |
| `user_last_click_article_w2v_sim`    | 与最近阅读文章语义越相似 → 点击概率高 |
| `article_id_cnt`                     | 热门文章（被多人点击） → 概率高       |
| `user_last_click_created_at_ts_diff` | 发布时间越近（新内容） → 概率高       |
| `user_id_category_id_cnt`            | 用户常看该类别 → 概率高               |
| `user_click_datetime_hour_std`       | 行为规律用户 → 概率稳定               |

LightGBM 会自动学习这些非线性组合。
